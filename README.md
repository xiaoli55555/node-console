# Node Console

苹果风格的 Debian VPS 监控面板。管理员管理接入的服务器、创建客户、分配服务器；客户登录后只看自己的 CPU、内存、磁盘、TCP 和 UDP 数据。

**v0.2.0 提供真实监控和正常系统重启，不依赖 PVE 权限。** 包含管理员／客户登录、随机密码生成与复制、客户服务器分配、TCP／UDP、流量、带宽历史、公网 IP 历史和运行时间。尚不包含远程终端、服务管理、强制重启、重装、订单、支付与自动开通功能。

## 部署要求

- 一台有 root 权限、使用 systemd 的 Debian VPS（建议 Debian 12/13），建议至少 1 GB 内存、10 GB 可用磁盘。
- 面板域名的 A 记录指向 VPS 的 IPv4 地址；若设置了 AAAA，也必须指向本机可用 IPv6。首次配置建议 DNS 直连。
- 放行入站 TCP 80、443，保留 SSH；Docker 需可下载镜像和 PyPI 依赖。
- 面板运行于 Docker，Caddy 自动申请 HTTPS 证书，数据库保存在独立 Docker 卷中。
- 没有域名时不要通过公网 HTTP 传输登录密码或采集密钥；先配置域名再运行安装脚本。

## 首次安装（公开仓库，无需 GitHub 登录）

在目标 Debian VPS 的 SSH 中，以 root 执行：

```bash
apt update
apt install -y git
git clone https://github.com/xiaoli55555/node-console.git /opt/node-console
cd /opt/node-console
bash scripts/install.sh
```

安装脚本会：询问面板域名，缺少 Docker 时从 Docker 官方安装源安装，构建镜像，让你交互输入管理员账号和密码，然后启动服务。密码不会写入 Git 历史；数据库仅保存密码哈希。请记住你自己设置的管理员密码。

首次安装通常需数分钟。完成后访问 `https://你的域名/admin`，使用刚设置的管理员账号登录。客户访问网站首页登录。证书申请失败可执行：

```bash
cd /opt/node-console
docker compose logs --tail=100 caddy
```

如果首次安装在写入 `.env` 后中断，不要删除数据库卷，可依次恢复：

```bash
docker compose build --pull
bash scripts/admin.sh
docker compose up -d
```

## 一条命令接入服务器

1. 管理员登录 → 服务器 → 添加服务器 → 填写名称。
2. 弹窗中点击“复制接入命令”。
3. 在目标 Debian VPS 的 root 终端粘贴并执行这一条完整命令。脚本自动安装所需依赖，不再询问面板地址或密钥。
4. 等待约 15～30 秒，面板出现真实数据。
5. 已有服务器也可点击列表行里的“对接命令”重新生成命令，成功接入时替换原密钥，保留服务器编号和历史。
6. 创建客户并分配服务器后，客户从网站首页登录。

命令中使用 10 分钟有效的一次性接入凭证，不包含长期采集密钥。凭证只能成功兑换一次，重新生成后旧命令失效。生成命令本身不影响已安装的客户端，成功兑换后旧采集密钥失效。不要向其他人分享接入命令，也不要在不同 VPS 上重复使用同一台服务器的命令。

客户端采集监控信息，并仅接受面板授权的正常重启任务，不提供任意远程命令执行。通过 HTTPS 主动向面板上报，不需要为客户端开放任何入站端口。配置保存在 `/etc/hk-sdan-agent/config.json`，权限 600。客户端启动使用 root，systemd 限制能力范围，旧版 UDP conntrack 查询使用 CAP_NET_ADMIN（新版 UDP socket 不依赖 conntrack），重启功能保留 CAP_SYS_BOOT。

```bash
systemctl status hk-sdan-agent
journalctl -u hk-sdan-agent -n 50 --no-pager
```

重新运行客户端安装命令可升级客户端；客户端不会远程自动更新代码。重置某台服务器的密钥后，需要在该服务器用新密钥重新安装／配置。旧密钥立即失效。

## 指标含义

| 指标 | 统计方式 |
|---|---|
| CPU | 两次采集之间 `/proc/stat` 的忙碌时间比例；首次采集为“—” |
| 内存 | `(MemTotal - MemAvailable) / MemTotal` |
| 磁盘 | 根目录所在文件系统的已用比例 |
| TCP | 当前网络命名空间中 `/proc/net/tcp` 与 `tcp6` 的 ESTABLISHED socket 数量，不含 TIME_WAIT 和监听 socket |
| UDP | v0.2.7 起使用 `ss -u -a -n -H` 统计 IPv4＋IPv6 UDP socket，包含监听及未连接 socket；不是 conntrack 会话数 |
| 累计网卡流量 | 除 lo 外网卡字节计数之和；可能因桥接／虚拟网卡重复计量，非供应商账单或月流量 |

新版 ss 不可用或采集失败时，UDP 显示“—”及原因。与其他监控软件的数字可能因统计口径不同而不同。TCP 也可能包含客户端本身与面板的连接。

浏览器每 5 秒刷新；超过 60 秒没有上报标记离线。列表与详情隐藏离线旧数值，保留最后采集时间。首页合计只汇总当前账号可见、在线且该项采集成功的服务器，不把缺失值当成零。

## 更新

```bash
cd /opt/node-console
bash scripts/update.sh
```

从公开仓库匿名拉取，无需登录 GitHub。脚本先备份 SQLite，再快进更新源码、构建镜像并重启，检查应用健康状态。账号、服务器分配及密钥不随代码更新清空。配置 `.env` 不提交到仓库。没有远程自动更新，只有你主动运行脚本时更新。

如修改了源码，脚本会暂停，避免覆盖本地改动。构建失败不会替换旧容器；按终端打印的 `apply-update.sh` 命令修复后重试。

更新脚本会短暂重启服务；健康检查验证应用接口，不等于验证公网 DNS、证书和防火墙。后续不兼容数据库升级必须先提供迁移和恢复说明。

## 备份与恢复

```bash
cd /opt/node-console
bash scripts/backup.sh
```

一致性数据库备份位于 `backups/`。数据库包含密码哈希、登录会话及服务器资料，需妥善保管；建议定期复制到其他机器。脚本同时将密码加密密钥保存为同名 `.db.key` 文件（存在该密钥时）。数据库和匹配的密钥必须一起妥善保存；丢失密钥后不能解密客户密码。另行保存 `.env` 域名配置。Caddy 证书在独立卷，可重新签发。不要执行 `docker compose down -v`，它会移除持久化卷。

恢复会覆盖当前数据库，先备份当前状态，确认恢复文件。停止应用后，将备份写回卷（将路径替换成你的备份）：

```bash
cd /opt/node-console
docker compose stop app
docker compose run --rm -T --user 0 -v "$PWD/backups:/restore:ro" --entrypoint python app -c 'import sqlite3,shutil,os; from pathlib import Path; source=sqlite3.connect("file:/restore/YOUR_BACKUP.db?mode=ro",uri=True); dest=sqlite3.connect("/data/panel.db"); source.backup(dest); dest.execute("DELETE FROM sessions"); dest.commit(); dest.close(); source.close(); key=Path("/restore/YOUR_BACKUP.db.key"); shutil.copyfile(key,"/data/credential.key") if key.exists() else None; paths=[Path("/data/panel.db")]+([Path("/data/credential.key")] if Path("/data/credential.key").exists() else []); [(os.chown(p,10001,10001),os.chmod(p,0o600)) for p in paths]'
docker compose up -d
```

恢复后会话已清空，需要重新登录。仅恢复与当前程序数据库结构兼容的备份。

回退代码：先备份，然后执行 `git switch --detach 更新前提交SHA`、`docker compose build`、`docker compose up -d`。如涉及数据库结构变化，先按该版本迁移说明处理；不要盲目将旧库覆盖新数据。回到更新通道使用 `git switch main`。

## v0.2.0：流量、带宽、IP 历史与重启

先更新面板：

```bash
cd /opt/node-console
bash scripts/update.sh
```

再到**每台被管理的 Debian VPS**以 root 执行（含需要监控面板本机时的面板 VPS）：

```bash
curl -fsS --proto '=https' https://panel.example.com/agent-update.sh -o /tmp/hk-sdan-agent-update.sh
bash /tmp/hk-sdan-agent-update.sh
```

升级脚本保留原有面板地址及接入密钥，无需重新创建服务器。若使用其他面板域名，请替换下载地址。更新后等待约 30 秒，在浏览器强制刷新页面。客户端升级过程中不会主动重启 VPS；只有管理员／对应客户确认提交重启后才执行重启。

### 流量与带宽

- 列表显示今日和本月接收／发送流量及当前下行／上行速率，详情提供最近 1 小时／24 小时动态曲线。
- 以 VPS 视角：接收为下行，发送为上行。带宽单位 bps/Kbps/Mbps/Gbps，流量单位 KiB/MiB/GiB/TiB，不混用位与字节。
- 速率根据连续两次网卡字节计数差和面板接收时间差计算，新版客户端每 5 秒上报／页面每 5 秒刷新，是区间平均值，不是逐秒瞬时值。超过 60 秒的缺报区间不计算当前带宽。
- 流量从升级面板后的两次有效上报开始累计，首次上报仅建立基准，不把服务器历史总计记入当日。重启或计数器回退时重新建立基准，未观测到的重启期间流量无法补算。
- 每日／每月按北京时间（UTC+8）统计；跨日区间按时间比例估算分摊。历史带宽样本保留 7 天，日流量保留 400 天。
- 仍使用客户端“除 lo 外所有网卡字节之和”，桥接、容器或 VPN 虚拟网卡可能重复计量，不能当作上家计费依据。没有成功采集的数值显示“—”。

### 公网 IP 历史

- 新客户端读取网卡上的公网 IPv4／IPv6，记录地址集合变化；没有变更时不重复写入。
- 管理员可看所有机器，对应客户只看自己的机器。记录时间是面板首次观测到变化的时间，不是精确的变更发生时间。
- 采集失败不会清空历史；旧客户端未上报 IP 时提示升级。IP 历史不设置条数上限，不自动清理；完整记录支持分页查看。
- NAT VPS 外部出口 IP 不一定出现在网卡；Agent 会独立采集出口 IP，但它可能是共享 NAT 或策略路由地址，不能直接等同于网卡地址。IP 监控仅在网卡公网 IPv4 缺失时回退到新鲜且唯一的出口 IPv4，并在 DNS 更新前验证业务 TCP 端口可达。

### 正常重启与运行时间

- 服务器列表和详情均显示系统运行天数、小时、分钟，并提供“重启 VPS”。
- 管理员或当前被分配的客户可重启，必须登录、通过 CSRF 验证并在页面二次确认。离线或未升级客户端的机器不可提交重启。
- 任务由客户端下次上报时接收。任务有效期 120 秒，一次下发、一次确认，不自动重试；重复点击会被限制。机器重新分配后，未执行的原客户任务失效。
- 执行内容固定为 `systemctl reboot --no-block`，没有可输入的远程命令。面板不保存 VPS SSH 密码。
- “已下发／客户端已确认”不等于重启成功。后续上报观测到运行时间下降才标记“已观测到系统重启”，10 分钟未确认则标记未确认。重启期间连接和业务会中断。
- 这是系统内正常重启，无法给已关机 VPS 开机，也无法在系统死机时通过上家虚拟化层强制重启。

### 数据库升级

本次仅增加流量、带宽历史、IP 事件和任务表，应用启动自动创建，既有账号、服务器分配和接入密钥保留。更新前仍由脚本先备份数据库。

## 独立管理员入口

- 客户入口：`https://panel.example.com/`，仅接受客户账号。
- 默认管理员入口：`https://panel.example.com/admin`，仅接受管理员账号。
- 管理员登录 → 后台设置 → 管理员登录入口，可将 `/admin` 改为其他路径，例如 `/manage/panel-123`。
- 修改后旧路径返回 404，所有管理员会话失效，并自动转到新路径重新登录；客户登录不受影响。请立即收藏新地址。
- 不在客户页面展示管理入口链接。入口路径不是密码替代品，仍需使用强密码。
- 忘记当前管理路径，在 VPS 执行：

```bash
cd /opt/node-console
docker compose exec -T app python server.py entry
```

升级前已登录的管理员可能需要从 `/admin` 重新登录；原管理员账号和密码保留。

## 客户列表快捷操作

客户列表提供复制账号、复制密码和分配服务器。管理员可随时查看、复制和修改客户用户名及密码。新建或修改后的客户密码加密保存，刷新或重新登录后仍可读取。旧客户仅有密码哈希，原密码不能还原，需管理员先设置一次新密码。服务器分配可勾选空闲服务器或解除当前客户分配，其他客户名下的机器需先解除原分配。


## CMHK 重启换 IP：完整历史（v0.2.1）

服务器列表每一行都有“历史 IP”按钮，管理员及对应客户可查看。记录包含变更前地址、变更后地址和首次发现变化的北京时间；首次接入标为“首次记录”。无变化时不重复记录。

客户端使用独立接入密钥，不绑定 VPS 的当前 IP，所以 CMHK 重启换 IP 后继续更新同一台服务器的历史。请保留客户端配置，不要为同一台机器反复创建新的服务器条目。

历史不自动清理、不设置 1000 条上限。页面每次加载 50 条，点击“加载更早记录”可查看全部。备份会包含历史记录。历史从客户端首次上报公网 IP 后开始记录，旧版本已经清理掉或此前未采集的记录无法补回。手动删除服务器会连同该服务器的历史一起删除。

变更时刻只能定位为“首次观测到新 IP 的时间”，断网期间的真实切换时刻无法精确推断；如果 VPS 在两次上报间多次换 IP，只能保存实际观测到的地址。

## 可点击动态指标窗口（v0.2.2）

管理员和客户的服务器列表中，点击 CPU、内存、网络带宽、TCP 或 UDP 数值，即可打开动态监控窗口。窗口内可切换指标、选择最近 1 小时／24 小时，每 5 秒自动刷新，悬停单指标图表的采样点可查看时间和数值。

CPU、内存、TCP、UDP 的历史从本次面板更新后开始保存，保留 7 天；不需要升级客户端。网络窗口继续使用已有带宽历史。1 小时曲线按 15 秒桶聚合，24 小时曲线按 6 分钟平均值聚合；页面所示区间峰值为聚合点峰值。离线隐藏当前数值，保留历史；断报区间不连线。

后台和客户共用相同指标能力，但客户只能请求自己名下服务器的监控接口。新增历史表自动创建，既有账号、IP 历史和接入密钥保留。

## 一键接入更新（v0.2.3）

只需更新面板 `bash scripts/update.sh`，之后添加服务器或点击“对接命令”即可取得新版单行命令。既有已连接的服务器无需重新接入。手动运行 `/agent-install.sh` 仍可使用交互式填写地址、密钥的模式。

如果凭证过期或已使用，请重新生成命令。客户端安装涉及 apt 下载，若超过 10 分钟才到凭证兑换步骤也需要重新生成。接入服务端先验证一次性凭证，再生成只属于该服务器的长期密钥；长期密钥写入目标 VPS 的 600 权限配置文件，不打印到终端。

## 管理员查看及修改客户凭据（v0.2.4）

客户列表保留“创建客户”和“分配服务器”，并提供“复制账号”“查看密码”“复制密码”“修改账号／密码”。不再限制为创建当次可复制。

新建、管理员重设、客户自行修改后的密码，同时保存登录用哈希和加密后的可恢复副本。只有通过鉴权及 CSRF 检查的管理员能读取，读取操作写入审计日志。密码不存入浏览器 localStorage，关闭查看弹窗会清空其内容。

加密使用 Fernet，密钥位于应用数据卷 `/data/credential.key`，与数据库分开存放，不提交 GitHub。后续升级保留数据卷；备份脚本同时备份数据库和加密密钥。保管好匹配的 `.db` 与 `.db.key` 文件。只有数据库备份、没有对应密钥，就不能恢复这些可查看密码。

原有仅含哈希的客户密码不能逆向恢复，需设置一次新密码；原账号仍可用原密码登录。管理员修改客户用户名或密码后，客户现有登录会被撤销，服务器分配不变。


## 动态监控窗口（v0.2.5）

管理员与客户的服务器列表均可点击 CPU、内存、网络、TCP、UDP，打开同一套监控窗口。客户仍仅能访问分配给自己的服务器。

- 当前值、区间平均和区间峰值；CPU 蓝色、内存紫色、TCP 橙色。
- 网络上下行双曲线、今日与本月流量；悬停或触摸曲线查看采样时间与数值。
- 最近 1 小时 / 24 小时切换，每 5 秒自动刷新，可暂停或手动刷新；关闭窗口停止轮询。
- 1 小时按 15 秒时间桶、24 小时按 6 分钟平均值聚合；平均与峰值基于可见聚合点，不等于原始瞬时峰值。断报不连线，离线不展示旧数值为当前值。

仅需更新面板，无需额外安装其他探针。页面设计参考 Komari 的轻量监控定位和 Netdata 的指标分组交互，以本项目现有苹果风格重新实现，未引入其源码或资源。参考：https://github.com/komari-monitor/komari 、https://learn.netdata.cloud/docs/dashboards-and-charts/tabs/metrics 。


## 低负担采集频率（v0.2.6）

- 新版 Debian Agent 每 5 秒采集并上报 CPU、内存、磁盘、网卡计数、运行时间和网卡公网 IP。面板页面每 5 秒轮询，采集与页面轮询并非同步，不能保证 5 秒内展示。慢请求或采集超时可能延迟。
- TCP／UDP 扫描每 15 秒一次，其余上报复用最近一次结果；正常上报不逐条写日志。
- 历史曲线至多每 15 秒保存一个实际采样点；当前状态及流量累计仍每次上报更新。因此实时数据会比历史曲线更新更频繁；仍有每 5 秒的状态及流量数据库写入。
- 出口 IP 在独立后台线程每 60 秒通过 HTTPS 查询 api.ipify.org（IPv4）及 api6.ipify.org（IPv6），单次请求超时 3 秒。检测不携带面板密钥，绕过代理环境变量，失败不阻塞资源上报。无 IPv6 时部分检测失败属正常。显示检测时间，超过 90 秒不再作为当前出口 IP 展示。
- 出口地址是访问上述服务时观察到的地址，不一定代表所有策略路由目的地。历史 IP 优先记录 90 秒内的出口公网 IP，没有可用出口结果时记录网卡公网地址；空结果和采集失败不会清空历史。

先更新面板，再在每台被监控的 Debian VPS 执行客户端更新（替换你的域名）：

```bash
curl -fsS --proto '=https' https://你的面板域名/agent-update.sh -o /tmp/node-agent-update.sh
bash /tmp/node-agent-update.sh
```

已有密钥、分配及服务名称不变。只更新面板时，旧客户端仍保持原有 15 秒上报。升级前后均应以 VPS 实际 CPU／内存占用判断负担，未承诺固定占用比例。


## UDP socket 口径（v0.2.7）

根据实际 VPS 上 `ss -uanH` 返回 177、conntrack 返回 0 的排查结果，UDP 改用 `ss -u -a -n -H` 的非空行数。此口径包含 IPv4／IPv6、监听与未连接 socket，不代表实际 UDP 对端会话数；NY 的内部实现未验证。每 15 秒采集，页面每 5 秒更新。

### IP 与解析 API（管理员）

后台新增「IP 与解析 API」：

1. 添加「阿里云 API」，填写名称、RAM AccessKey ID、AccessKey Secret。RAM 权限需要查询所选域名记录、查询记录详情及修改记录；仅授予需要的域名。
2. 点击「测试 / 获取记录」，输入主域名。结果包含 RecordId、RR、Line、Value、TTL；最多显示前 100 条，记录多时请同时核对阿里云控制台。
3. 优先使用已接入 Agent 上报的**唯一网卡公网 IPv4**；若网卡没有公网 IPv4，则回退到 Agent 每分钟采集的唯一出口 IPv4。出口地址可能受 NAT 或策略路由影响，只有业务 TCP 端口验证通过才会允许 DNS 自动更新。另一家可添加只读 GET HTTPS API，填写完整服务器查询地址、认证头、凭证前缀及 JSON 字段路径，例如 `data.ip` 或 `data.servers.0.ip`。一个 API 连接对应一台服务器，IP 字段必须返回公网 IPv4 字符串。URL 不要包含密钥，使用凭证栏。
4. 点击「绑定解析记录」，选择服务器、阿里云连接和主域名，点「读取这个域名的 A 记录」，再从显示的主机记录、运营商线路、当前 IP、RecordId 中选中一条；RR、Line、RecordId 和旧 IP 自动带入，另选 IP 来源及实际业务 TCP 端口。保存时会再次查询阿里云核对记录身份与当前值。
5. 先用「检查」观察 `旧 IP → 新 IP`；新 IP 至少稳定 60 秒后，可点「同步」。验证完成再在绑定编辑中开启自动同步。同一主机记录按电信/联通/移动等线路返回不同 IP 时，每个 RecordId 各建一条绑定，并指向对应的 VPS；同一台 VPS 可绑定多个记录，但只有它实际提供相同 IP 时才这样配置。

**旧 IP 核对保护**：更新前读取指定 RecordId，核对 RR、A 类型、线路、启用状态及旧值。只替换该绑定明确选择的 RecordId/Line，且当前值必须等于该记录旧 IP；同域名的其它运营商线路不会被连带修改。如果人工或其他程序已更改旧值，停止并显示原因；核实后编辑绑定重新保存。不会按 IP 扫描并改写所有域名。阿里云接口没有原子 compare-and-swap，写前再次回读可以缩小竞态窗口，但不能完全消除与控制台/其他程序同时写入的竞态；请保持一套程序负责这些记录。

自动同步由 Compose 中的 `dns-worker` 每约 10 秒运行一轮，轮询耗时随绑定数量和 API 响应增加；与网页按钮共用进程锁，避免重复并发写入。agent 超过 90 秒未上报、多个 IPv4 无法判断、API 失败、旧值不符或新 IP TCP 不通时暂停。任何异常会重置新 IP 稳定计时。DNS 更新保留原 TTL 和线路，修改后回读核对，客户端缓存仍可能持续到 TTL 到期。权重配置不作为写入参数更改。

密钥通过已有 `credential.key` 加密存储，读取接口不返回明文；备份必须同时保留数据库和对应密钥。API 请求校验 HTTPS 证书，不跟随重定向，并阻止指向私网/本机地址。已有连接变更账号或 URL 时要求重新填写凭证。

**检测与自动响应边界**：本系统将连续完整多点 TCP 失败标记为疑似不可达，不会宣称已证实被墙；可选自动重启或通用 HTTPS JSON 换 IP API，但不支持任意云商专用签名协议。不会验证 UDP/代理协议握手，也不自动发送通知。自动判墙与换 IP 需要供应商/探针接口文档后按其格式接入，不将单一 TCP 失败判定为被墙。本阶段仅同步 IPv4 A 记录，AAAA/CNAME 不会修改。

更新后检查：`docker compose ps` 应出现 `dns-worker`；查看日志用 `docker compose logs --tail=100 dns-worker`。首次部署不创建绑定、不修改 DNS，也不重启节点。

「IP 监控与解析」现在提供独立的 VPS 选择界面：点击「选择 VPS 加入监控」批量勾选已有服务器；每台以卡片展示当前 IP、上一个 IP、端口、最近检测时间与结果。按钮包括「立即检测」「配置」「绑定解析」「换 IP 记录」「移出监控」。配置中可选择 agent 或服务器 API 作为 IP 来源，并暂停/恢复此 VPS 的后台检测与自动解析任务。解析绑定只能选择已加入监控的 VPS；移出前必须关闭该 VPS 的自动解析绑定。记录历史按钮显示 agent 的公网 IP 历史（优先出口探测结果，回退网卡公网地址），API 来源的变化可在本页同步日志查看。添加监控不会自动修改 DNS。统计卡片中的「记录到 IP 变化」是存在上一个 IP 的 VPS 数量。

### 独立的「检测点配置」

此菜单与 DNS 绑定分离，可随时将一台 VPS 的检测来源从 BOCE 切换为自建探针，或更换 BOCE 节点，不需要改动阿里云解析绑定。

1. 在「IP 监控与解析」选择被监控 VPS，并设置 IP 来源、业务 TCP 端口。
2. 在「检测点配置」添加来源：BOCE（API Key 加密保存）或自建探针（系统生成独立密钥，仅显示一次）。可重命名、暂停和删除未使用来源。
3. BOCE 点击「获取国内节点 / 测试连接」，按地区与运营商显示官方节点列表；此调用不创建 TCPing 检测任务。给 VPS 配置检测点时，可勾选节点或填写节点 ID，最多 20 个。
4. 为每台 VPS 设置来源、检测间隔（至少 120 秒，默认 600 秒）、每日节点检测次数上限（默认 1000）和定时开关。默认仅手动运行。页面显示理论每天节点用量；BOCE 实际扣费以其账单为准。
5. 「立即检测」会明确提示 BOCE 可能产生用量。任务提交后由 worker 每约 10 秒查询一次结果，最多等待 2 分钟；在任务完成或超时前不重复提交。单次提交发生网络异常时，保留用量预留及冷却，不自动重试同一任务，避免重复扣费。
6. 面板展示任务 IP、端口、来源和每个节点的可达性、延时。未完成、缺少节点、节点离线、接口异常、余额不足、过期任务均不判定为目标被墙。可选自动处理仅在定时检测中生效：所有所选节点完整返回 TCP 不通且连续达到阈值（2–5 次，默认 3 次）时，才可请求 agent 重启；手动检测、部分节点不通及未知结果不会触发。自动重启不设一小时冷却，已有在途重启任务时不重复排队，并要求 agent 在线且支持 reboot。端口连通不代表应用协议可用；TCP 全部失败也只表示“疑似不可达”，不等同于已证实被墙。
7. 自建探针部署见 `probe/README.md`。探针通过 HTTPS 主动领取任务并上报，对任务 ID、来源密钥、目标 IP、端口、时效及重复结果进行校验。不需要向国内设备发起入站连接。更换自建检测点：添加新来源、部署探针、切换 VPS 计划，再移除旧来源。

自动 DNS 同步仍独立工作：只有服务器报告了新 IP，且旧值核对、稳定时间和控制端 TCP 检查通过后，才更新已绑定的 A 记录。DNS 绑定默认要求新 IP 出现后的一次完整探测中，当前端口的所有所选节点均可达才允许同步；管理员可对单条绑定关闭此复检要求。检测确认后请求重启不保证云商分配新 IP；检测到 agent 重启后，会立即安排下一轮探测（通常 5 秒内启动），不再等待常规检测间隔。公网 IP 一变化也会立即安排一次全节点探测，通过后即可同步 DNS。自动重启默认关闭，需管理员为每台 VPS 单独选择策略并开启定时检测。换 IP 支持管理员配置通用 HTTPS JSON POST API，可在请求 JSON 中使用 `{{server_id}}`、`{{server_name}}`、`{{current_ip}}` 占位符；仅在连续完整失败达到阈值后启动恢复流程；换 IP API 不设一小时冷却或重试次数上限，明确失败后逐轮重试，直到新 IP 复检通过或手动暂停。供应商要求专用签名、非 JSON 参数或不同协议时，仍需按其 API 文档开发适配器。自建探针来源名称中的地区/运营商由管理员填写，系统无法独立认证其真实网络。

BOCE 官方文档：创建任务 https://www.boce.com/document/api/162/161 ，结果 https://www.boce.com/document/api/162/43 ，节点 https://www.boce.com/document/api/70/72 。代码使用固定 BOCE 域名，按官方示例通过 GET 查询参数发送请求，不把带密钥的 URL 写入日志。由于未配置真实 Key，付费 API 尚未实测；上线前先用少量节点手动验证。


### 一键配置 IP、探测与 DNS

「IP 监控与解析」提供「一键配置检测、换 IP 与 DNS」向导。先选择 VPS，系统会自动加入监控并读取当前 IP；再选择已启用的 BOCE/自建探针来源、节点及检测间隔，设置连续完整失败后的处理方式（仅记录、agent 重启或 HTTPS JSON 换 IP API），最后查询阿里云 DNS 并选择要绑定的 A 记录。

向导在保存时会先创建手动 DNS 绑定，再保存探测计划；仅当全部步骤成功后才按管理员勾选启用自动 DNS 同步，失败时绑定保持手动状态。DNS 旧 IP 保护和 TCP 可达检查仍然生效。向导默认自动 DNS 同步未勾选；重启/API 动作需同时开启定时探测并通过连续失败阈值。换 IP API 配置不会试发请求；供应商接受请求后仍需等待 Agent/只读 IP API 上报新 IP，随后 DNS worker 才会更新已绑定记录。

### 每台 VPS 的自动换 IP 开关

在“IP 监控与解析”的机器卡片中，已配置换 IP API 或自动重启的 VPS 显示独立开关。暂停仅关闭自动动作，BOCE 探测和既有 DNS 同步继续；取消尚未执行的自动换 IP 请求与关联自动重启命令，不影响手动重启。恢复后从新任务重新累计失败次数；自动重启和换 IP API 均无一小时冷却；暂停前在途结果不会触发动作。已提交给供应商的请求或已开始的重启无法撤回。未配置动作时先完成检测计划配置。

### 新 IP 复检与持续恢复

换 IP API 的明确失败会立即重新排队，在下一轮后台循环（通常约 10 秒）重试，没有一小时冷却或次数上限。请求已受理、网络超时或结果不确定时，先根据新鲜 Agent/API IP 核对结果；最多观察 60 秒仍未发现变化才重新请求。这是等待供应商完成和 IP 上报的窗口，不是换 IP 冷却，避免多个请求同时更换地址。工作进程重启会保留请求状态。

发现新 IP 后立即安排一次完整探测。若任一国内节点明确不通，连续达到现有失败阈值后继续换 IP；接口异常、缺失结果不当成被墙。当前端口和所有所选节点都通过后即可更新 DNS，不再等待第二轮或额外稳定时间。勾选该选项时需开启定时探测；未配置或未开启探测计划会保持旧解析。控制端业务端口检查、旧值与线路 RecordId 校验及回读仍保留。DNS 写入失败不再次更换已经通过国内复检的 IP；解析异常仍由原有旧值与线路保护处理。

面板机器卡片显示换 IP 恢复进度、请求次数、等待上报/复检/解析同步状态。手动暂停可停止后续请求；已发送请求不能撤回。BOCE 探测仍受所配置的频率、每日节点次数上限及账户余额约束。自动重启不设一小时冷却，保留在途任务去重。

自动探测首次确认不通后，10 秒后安排下一次复测；连续失败达到配置阈值才触发动作。恢复可达后返回常规探测间隔。实际执行受后台轮询、上游结果返回时间及调用额度约束。

加速恢复：后台循环由 10 秒缩短至 5 秒；BOCE 结果查询仍至少间隔 10 秒，日调用上限保留。已受理或结果不确定的换 IP 请求观察窗口为 60 秒；发现新 IP 后立即复检，一轮全节点可达后立即同步 DNS。供应商执行、Agent 公网 IP 查询和 DNS TTL 仍可能增加实际恢复耗时。

DNS 绑定可分别选择“新 IP 先做一次国内探测再解析”（默认开启）。关闭后跳过 BOCE 一轮门槛及 IP 稳定等待，获取到新 IP 后立即尝试更新该线路记录；阿里云旧值与 RecordId/Line 核对、控制端业务 TCP 检查、写入后回读仍执行，TCP 不通或任一校验失败会暂停更新。

### 客户自助控制 IP 自动解析

客户在自己名下 VPS 的详情弹窗中可配置个人 BOCE API Key、国内节点、探测间隔、每日额度及定时开关，也可查看已配置 DNS 线路并开启或暂停自动解析。客户配置只接受该客户该 VPS 专属的 BOCE Key，不会调用管理员或其他客户的 Key；密钥在服务端加密保存，页面不会回显。若管理员已启用该 VPS 的自动重启或换 IP 策略，客户不能更改或重新开启这组探测设置，只能暂停定时探测；管理员关闭自动动作后，客户才可调整配置。服务器转交给其他客户时，系统会清空原客户 Key 并停用关联的旧计划。客户不能改 DNS 域名、线路或阿里云凭证；新 IP 的 DNS 更新仍要求所选节点完整探测通过。BOCE 节点选择按节点任务计费，请按需控制节点数、探测频率和每日额度。接口按服务器 owner_id 校验归属并记录审计日志。管理员仍需先为 VPS 开启 IP 监控；未配置 DNS 绑定时客户可单独使用探测设置。

### 双 VPS 定时轮换

客户可在第一台 VPS 的“自动换 IP 服务”详情中配置另一台自有 VPS、该主机已绑定的一条 DNS A 记录、每台承载时长及旧机 TCP 连接阈值。默认每台承载 2 小时、阈值 80。计划启用前，两台 VPS 都必须开启 IP 监控与个人 BOCE 定时探测，并分别配置自己的换 IP API；DNS 绑定必须属于当前客户和主 VPS，且原有单机自动解析需暂停。

到时后，系统先确认备用机 IP 新鲜、业务端口可达且当前 BOCE 结果通过，再更新并回读 DNS。旧机至少等待记录 TTL（加 60 秒缓冲），并要求两次新的连接采样都严格低于阈值，才触发该旧机已配置的换 IP API。新 IP 上报、业务端口可达且通过该机当前 BOCE 节点复检后，旧机重新成为备用机。轮换任务串行运行；旧机连接不下降、BOCE 失败或 API 未完成时会保持当前承载机并显示等待状态。暂停会停止后续流程；已发出的 API 请求不能撤回。DNS 缓存可能使部分客户端在 TTL 后仍访问旧地址。

轮换时间支持按分钟调整（1 分钟至 7 天）。当前承载 IP 的最新 BOCE 全节点结果均不通时，优先切回另一台已通过 BOCE 和业务端口检查的 VPS；故障机跳过 TTL 和 TCP 阈值直接换 IP。备用机正在换 IP 或复检、或者不可达时不会盲目修改 DNS。新 IP 复检仍不通会继续换 IP，通过后恢复定时轮换。

配置优化：选择两台客户自有 VPS 和主机的 DNS 记录后，可先执行只读配置预检，逐项列出 BOCE、IP/TCP 上报、专属 API 和 DNS 核对结果。启用轮换自动接管所选记录并暂停其单机自动解析；不需要另行启用被墙自动动作。周期和 DNS 提前发布量分别按分钟设置，例如 120 分钟周期、提前 2 分钟表示第 118 分钟切换，旧机保留 TTL 及连接排空时间。接近切换时刷新探测（每台不超过每 60 秒请求一次刷新，仍受 BOCE 配额约束）；备用机检查必须新鲜。备用 IP 提前不通会在保持当前 DNS 的情况下修复。备用机恢复后保留当前周期的切换时间，避免每次修复都把轮换时间向后重置。

离线处理：当前承载 VPS 连续 15 秒无 agent 心跳（可配置 10～120 秒）时，使用 DNS 绑定的旧值核对解析并切换到健康备用机（仍须新鲜 BOCE 和 TCP 检查）。离线旧机不凭心跳消失调用换 IP API，等待恢复后再检查连接/探测；两台均离线时保持 DNS 并显示无可用备用机。

agent 每 5 秒上报一次。默认无心跳阈值 15 秒，对应约 3 次缺失；后台每 5 秒推进一次，通常在约 15～20 秒开始提交故障切换，DNS API 与客户端缓存耗时另计。该阈值用于业务切换，不将心跳丢失等同于物理关机。

### 轮换实测统计与只读分析接入

增加 IP 存活时段、DNS 提交/回读、实际地区/运营商 DNS 观察和换 IP 恢复耗时统计。客户轮换详情可生成只读分析令牌和 DNS 观察节点安装命令；管理员 IP/DNS 页面可查看汇总。样本不足不给出候选最优周期，建议不会自动修改生产配置。Cloudflare 代理源站变化及运营商分线路不能当成全国 A 记录传播。完整部署、权限和数据口径见 [轮换实测与分析接口](docs/rotation-insights.md)。

后台侧栏新增「双 VPS 轮换」，支持管理员创建、预检、编辑、启停和删除轮换。后台新计划只接受后台检测来源、检测计划明确指定的换 IP API 和后台 DNS 绑定；管理已有客户计划时保留其原归属与凭证范围。后台统计页可生成、复制及撤销每组轮换的只读分析接口，无需切换客户账号。

后台创建轮换支持直接选择已保存的 DNS API、自动读取域名和 A 记录，再明确选择记录及运营商线路；无列域名权限时可手填已授权主域名。点击“选用此记录”只保存面板绑定，不修改供应商 DNS；会核对主 VPS 的新鲜公网 IP、记录身份和线路，拒绝覆盖其他 VPS 的绑定。


### 两种 VPS 轮换模式

升级后已有任务保持 **双机交替轮换（原模式）**；后台与客户端轮换表单均可选择模式。更改模式前必须暂停、完成回收流程并让当前承载回到主 VPS，避免运行中重释状态。

**固定主机＋移动线路轮换（新增）**：选择主 VPS A、轮换 VPS B 和一条移动线路记录（或移动专用域名），明确确认记录仅服务移动。其他运营商记录不加入该任务。配置周期、B 的接替时长和首次切入时间。首次时间按浏览器本机时区输入；留空或过期时从启用起等待一个周期。接替时长必须小于周期；该模式不使用原模式的提前发布量。

1. 首次到时，B 当前 IP、国内探测和业务端口均通过后，仅将选定记录从 A 切到 B。A 不排空、不重启、不更换 IP。
2. B 接替时长到期，先验证 A，验证通过后切回 A；A 不可用则延后切回并在状态中显示原因。
3. 切回后保留 B 服务，等待 DNS TTL 加 60 秒；连续两次不同采样的 TCP 已建立连接总数严格低于阈值（默认 80）后，才执行 B 换 IP。80 不满足条件。使用现有 agent 的 `tcp` 和 `connections_sampled`，不要求 `tcp_by_port` 或专门升级 agent。TCP 总数包含 SSH 和代理出站等已建立连接；缺失/过期/无效采样仍阻止换 IP，不会按 0 处理。
4. B 新 IP 复检通过后待命，下一次切入按上次切入加周期安排。若恢复超过下一次时间，延后到恢复后再等一个周期，避免追赶调度导致连续动作。连接不下降就持续等待。
5. 主 VPS 仅在现有国内探测确认当前 IP 不通时进入故障修复，单纯心跳离线不会触发主 VPS 换 IP。故障切换同样必须验证接替机；后台可查看状态、倒计时和轮换记录。

DNS 修改不能强制清除客户端缓存；阈值换 IP 仍可能断开 B 的剩余连接。新模式首次启用不会立即给 B 换 IP，若 B 当前 IP 已健康则先用于首次接替；之后每轮退出并达到阈值才刷新。

更新面板仍使用原更新流程：在面板主机的项目目录执行 `bash scripts/update.sh`。新模式不要求业务端口统计；仅当现有 agent 尚未提供 TCP 总数及采样时间时，按需更新 agent：

```bash
curl -fsS --proto '=https' https://hksdan.top/agent-update.sh -o /tmp/hksdan-agent-update.sh
bash /tmp/hksdan-agent-update.sh
```

如面板域名不同，请替换 URL。脚本只更新采集程序并重启采集服务，保留接入配置；不会重启 VPS 或主动换 IP。更新后再运行表单预检并保存新模式。实际自动换 IP / DNS 调度仅在计划启用后执行。


固定主机模式与 A 原自动换 IP 的协调：

- 不新增三网检测。每台机器只使用其检测计划中选定的节点、当前 IP 和端口；按该计划配置的连续失败次数确认故障，未知/缺失/过期结果不算失败。任意一次完整通过仍可用于恢复验证。初次失败后加急复测，仍遵守来源启用状态、检测额度和任务并发限制。
- 轮换启用期间，独立检测器继续采集结果，由轮换协调器统一安排两台机器的自动动作，避免独立检测器和轮换器重复重启同一台。A 的其他自动解析记录继续按原来的校验和同步逻辑更新；移动绑定由轮换独占，A 新 IP 不会覆盖仍指向 B 的移动记录。
- A 在 B 等待排空但尚未发出动作时故障，取消 B 回收并重新验证 B，切入 B 后修复 A。B 已提交换 IP / 重启时不覆盖其进行中的状态，先完成 B 新 IP 验证，再故障接替及修复 A。A 在 B 接替期间恢复新 IP，验证通过后优先切回。
- 每次发出或重试自动换 IP 前，再检查当前承载机的所选节点结果（完整结果不超过 90 秒）、当前 IP、端口和未完成命令；过期就加急补测。只有两台都被所选节点确认不通时，才允许先修复非当前承载机；仍不同时提交两台动作，B 的连接阈值也不跳过。若 B 连接数始终不低于阈值，两台都故障时仍可能持续中断。
- 心跳丢失不单独触发新模式的故障换 IP 或应急切换。未结束的重启、结果不确定的请求不能被当作健康备用。重启 180 秒后无新 IP 会提示检查，不自动反复重启。
- 移动 DNS 写入前保存待核对记录。API 超时或进程中断后，先回读实际 DNS；确认新值后恢复状态，不重复写入；仍为旧值或第三方值时暂停切换及换 IP，显示待核对原因。无健康备用、检测未知或供应商动作未结束时，系统保留当前解析并明确显示等待原因，不能保证故障期间零中断。

### A 下线时的独立故障转移 VPS（C）

后台和客户端的轮换设置新增“A 的故障转移 VPS”选项。A、B、C 必须是不同的三台机器。该选项可用于原双机交替模式及固定主机模式；选择 C 即独立启用，暂停 B 的定时轮换不会停用 C。C 需要开启自己的 IP 监控和所选检测点，但不要求配置换 IP API；配置期间独立检测器不会给 C 自动换 IP。

接替范围固定为 **面板中绑定给 A 的全部 DNS 记录**，不能只选择部分记录。运行时会纳入新增的 A 绑定；不扫描或修改未绑定到面板的服务商记录，也不会修改绑定给其他 VPS 的记录。所有记录必须属于本计划的管理员/客户凭据范围。C 必须提前运行兼容的转发服务，支持 A 的所有业务端口；保存及切换时会检查端口可达性，TCP 探测不能代替真实业务转发验证。

- A 心跳超过现有“无心跳切换阈值”（默认 15 秒）时，C 的当前 IP、其所选检测点的近期完整结果和业务端口均通过，且没有未完成动作，才开始接替。心跳丢失只触发接替，不会据此给 A 换 IP。
- A 下线、移动当前指向 A：包括移动在内的全部 A 绑定切到 C。
- A 下线、移动已经由 B 承载：未确认 B 故障时保持移动在 B，A 的其他绑定全部切到 C。B 也心跳超时或所选点达到故障确认条件时，移动也交给 C。
- 接替记录由故障转移独占，A 原来的自动解析同步不会将其覆盖回 A。A/B 的轮换和回收流程暂缓；已经发出的动作保留状态，不会伪装成完成或重复发送。
- A 恢复后，使用 A **当前新 IP** 和其所选检测点验证，默认稳定等待 60 秒（可设 15～3600 秒）再切回。心跳再次丢失或检测未知会重置稳定窗口。如果 C 此时不可用，而 A 已验证可用，则优先切回 A。B 正常承载的移动记录保持原轮换流程。
- DNS 每条记录分别保存待核对状态并回读。请求超时后不盲目重复写入；外部修改、结果未知会保持接管并显示原因。接管期间禁止删除、修改相应绑定，或移除/转移相关 VPS。
- 要停用 C，应等接替记录安全切回后选择“不启用”，或者删除已暂停且没有未完成流程的轮换计划。

仅两种轮换模式的既有行为在不选择 C 时保持不变。C 不可用且 A 也不可用、DNS 服务商异常或客户端缓存未刷新时，不能保证零中断。测试覆盖及限制见 [故障模拟报告](docs/primary-failover-simulation.md)。
