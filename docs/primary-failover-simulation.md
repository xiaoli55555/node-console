# A/B 轮换与 C 故障转移模拟报告

测试对象：保留双机交替轮换，新增固定主机＋移动轮换，配合独立的 A 下线故障转移 C。

## 接替范围

**C 接替面板中绑定给 A 的全部解析，不只是移动，也不是人工选择的部分记录。**

A 下线且移动已由未确认故障的 B 承载时，移动保持 B；A、B 都下线时，C 使用 A 的节点完成本次拨测后也接替移动。不属于 A 的绑定和未绑定到面板的记录不修改。

## 故障注入覆盖

| 注入场景 | 验证结果 |
|---|---|
| 原双机交替模式，A 下线 | C 接替 A 全部绑定，保留原模式 |
| 固定主机模式，A 下线，移动在 A | A 全部绑定切到健康 C；无额外换 IP 动作 |
| A 下线，移动已在健康 B | 移动保持 B，其他 A 绑定切 C |
| A、B 同时下线 | C 验证通过后接替全部 A 绑定，包括移动 |
| A 短暂缺失心跳但未到阈值 | 不触发 C |
| C 心跳超时、所选检测点失败或业务端口不通 | 不发布 C 的 IP |
| C 有已接受的重启任务 | 不将流量切入 C |
| 闲置 C 尝试自动拨测、重启或调用换 IP API | 不创建新任务，动作被阻止或取消 |
| A 恢复且取得不同的新 IP | 稳定窗口后切回新 IP，不使用保存的旧 IP |
| A 心跳恢复，但所选检测点未通过 | 继续 C 接替 |
| A 反复上线、下线 | 重置恢复稳定窗口 |
| C 故障，而 A 已恢复并验证通过 | 优先恢复 A，不额外等稳定窗口 |
| A 正在换 IP 时下线 | C 接替其他记录，保留 A 动作；恢复不互相等待卡住 |
| B 的换 IP 请求已发出时 A 下线 | C 接替 A；B 动作状态保留，恢复后继续核对 |
| A 独立 API 流程等待 DNS 验证 | 验证新 IP 后允许切回，避免与 C 接管互相等待 |
| DNS 写入已生效，但供应商响应超时 | 回读确认，恢复状态，不重复提交同一次写入 |
| DNS 结果未知或被外部改成第三个值 | 不盲目覆盖；保持接管并显示待核对原因 |
| 接管时 A 普通自动同步尝试写回 | 被阻止，C 的解析不会被覆盖 |
| C 配置好后新增 A 的 DNS 绑定 | 新记录也接替；B 的无关绑定不受影响 |
| A 绑定有多个业务端口 | C 服务端口可达时全部接替 |
| 用户试图仅选 A 的部分绑定给 C | 拒绝，范围固定为全部 A 绑定 |
| 跨客户选择 C 或无效服务器编号 | 拒绝；失败保存不会留下部分配置 |
| 故障接替中删除、转移 VPS 或移除 C | 拒绝，保留恢复所需的状态 |
| 暂停 B 定时轮换 | C 仍独立保护 A，已有接管记录能安全切回 |

原固定主机测试另覆盖：A 故障撤销 B 尚未提交的回收、B 故障提前切回 A、使用现有 TCP 已建立连接总数（无需按业务端口统计），连接数等于 80 不触发、连续独立低值采样才触发、过期/缺失计数不当作 0、确认故障时跳过正常连接阈值、两台均失败时串行修复一台、候选 IP 和检测点更改后旧结果不可复用。

## 验证结果

后端全量回归 194 项通过，前端自动化 38 项通过；A/B/C 故障转移专项 42 项通过。JavaScript/Python 语法检查、Shell 语法检查及补丁空白检查通过。

## 测试方式与边界

- 后端使用真实 Flask 测试客户端、SQLite 数据库、权限校验、状态迁移及 DNS 记录身份/旧值校验。
- 探测结果、VPS 上报、重启/换 IP 结果及 DNS 供应商响应通过可控故障注入模拟；没有实际操作线上 VPS 或真实 DNS。
- 前端验证两个模式、第三台 VPS 选择、全部解析范围、请求参数、角色冲突和接管中的倒计时显示；JavaScript 语法检查通过。
- 容器文件清单导入与健康接口冒烟测试包含在后端回归中。当前环境没有 Docker，未执行 Docker 镜像构建。
- 浏览器点击测试因当前环境缺少浏览器且浏览器下载失败而未完成；不把渲染和参数测试表述为完整浏览器实测。
- 本地模拟不能证明 C 的真实转发配置、真实运营商可达性或客户端 DNS 缓存行为。C 与 A 同时不可用、供应商接口异常或 IP 动作结果不确定时，不承诺零中断。


## 冷备用继承专项

补充验证：C 没有独立探测计划和 IP 监控也能完成保存及只读预检；闲置 C 的定时/手动拨测不调用 BOCE；故障后复制 A 的节点、端口、频率、失败阈值及额度限制，必须等待 C 新任务完成；A/C 共享每日拨测额度；A 下线时暂停 A 的周期拨测；恢复后 C 停止拨测且不复制密钥；A 节点变更及暂停/恢复能传递到 C；停用冷备用恢复原配置；重启只作用 C，换 IP API 只使用 C 自身绑定，缺少 C API 时不会错误调用 A 的 API。


正常固定 A 模式：B 承载周期到期后，验证 A 并切回 A；B 连续两次 TCP 总数低于 80 后换 IP，新 IP 验证通过立即接替移动解析，并重新开始完整的 B 承载周期。A 的连接数不参与 B 回收。

故障优先：所选检测点确认当前 IP 不可用后，不等待承载周期、正常排空 TTL 或 TCP 阈值；有已验证健康的备用机时先切解析，再立即提交故障机换 IP。结果未知或过期不能当作被墙，也不能当作健康。新解析目标会加速安排一次原检测点复测。暂停只停止定时轮换，保留故障切换。
